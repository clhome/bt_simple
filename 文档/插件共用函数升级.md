# 插件共用函数需求分析报告

> 扫描范围：`plugins/` 下 41 个正式插件（排除 `待审核/`）
> 分析维度：安全性、执行效率、可靠性、代码复用

---

## 一、核心发现：最严重的重复问题

### 🔴 重复问题 #1：每个插件都重新实现了 API 请求函数（最高优先级）

**涉及插件：全部 41 个正式插件**

每个插件 JS 文件开头都定义了一组几乎完全相同的请求函数，仅仅是**插件名不同**：

| 插件 | 函数名 | 行为完全一致 |
|------|--------|------------|
| `mysql` | `myPost()`, `myPostN()`, `myAsyncPost()`, `myPostCallbak()`, `myPostCallbakN()` | ✅ |
| `redis` | `redisPost()`, `redisPostCallbak()` | ✅ |
| `docker` | `dPost()`, `dPostCallbak()`, `dPostOrgin()` | ✅ |
| `op_waf` | `owPost()`, `owPostN()` | ✅ |
| `fail2ban` | `f2bPost()`, `f2bPostCallbak()` | ✅ |
| `postgresql` | `myPost()`, `myPostN()` | ✅ |
| `supervisor` | `myPost()` | ✅ |
| `swap` | `swapPost()` | ✅ |
| `valkey` | `redisPost()`, `redisPostCallbak()` | ✅ |
| ... | ... | ✅ |

这些函数的**逻辑结构完全相同**，只有 3 个差异点：
1. `name` 参数值不同（即插件名）
2. 部分使用 `toArrayObject(args)` 序列化字符串参数，部分使用 `str2Obj(args)`
3. 部分使用 `/plugins/run` 端点，部分使用 `/plugins/callback` 端点

**变体清单**（按行为分类）：

| 变体 | 特征 | 出现次数 |
|------|------|---------|
| `xxxPost()` | 带 loading 遮罩 + 错误拦截 → `/plugins/run` | **41 次**（每个插件 1 次） |
| `xxxPostN()` | 无 loading 遮罩，静默请求 → `/plugins/run` | **7 次** |
| `xxxPostCallbak()` | 带 loading 遮罩 → `/plugins/callback` | **27 次** |
| `xxxAsyncPost()` | async/await 版本 → `/plugins/run` | **1 次**（仅 mysql） |

**总计：约 76 个几乎相同的函数定义散落在 41 个 JS 文件中。**

---

### 🟡 重复问题 #2：`str2Obj()` / `toArrayObject()` 工具函数重复

以下插件各自实现了 `str2Obj()` 查询字符串解析函数（逻辑完全相同）：
- `postgresql`, `phpmyadmin`, `webstats`（正式插件）
- `phpldapadmin`, `lam`（待审核）

`toArrayObject()` 疑似由面板核心全局定义，但仍有部分插件引用 `str2Obj()` 作为自定义替代品。

---

### 🟡 重复问题 #3：`randomStr()` 随机字符串生成函数

在 `postgresql` 中发现了自定义的 `randomStr()` 函数。这类工具函数应该由核心提供。

## 二、推荐新增的共用函数

基于以上分析，我建议在核心框架中新增以下共用函数：

### 共用函数 1：`YfPlugin.createApi(pluginName)` — 插件 API 请求工厂 ⭐ 最高优先级

**设计原理**：与 `createPluginTranslator` 一样采用工厂模式，一次注册、到处使用。

**函数签名**：

```javascript
/**
 * 为指定插件创建一套标准的 API 请求方法集
 * @param {string} pluginName - 插件目录名
 * @returns {object} { post, postSilent, postCallback, postAsync }
 */
YfPlugin.createApi(pluginName)
```

**返回对象包含 4 个方法**：

| 方法 | 说明 | 对应原有变体 |
|------|------|-------------|
| `api.post(method, args, callback, title?)` | 带 loading 遮罩 + 错误自动拦截 | `xxxPost()` |
| `api.postSilent(method, args, callback)` | 无 loading，静默调用 | `xxxPostN()` |
| `api.postCallback(method, args, callback)` | 通过 `/plugins/callback` 端点调用 | `xxxPostCallbak()` |
| `api.postAsync(method, args)` | 返回 Promise 的 async 版本 | `xxxAsyncPost()` |

**改造前后对比**：

```javascript
// ❌ 改造前：mysql/js/mysql.js 顶部有 5 个重复函数定义（约 100 行）
function myPost(method, args, callback, title) { /* 28 行 */ }
function myPostN(method, args, callback, title) { /* 18 行 */ }
function myAsyncPost(method, args) { /* 12 行 */ }
function myPostCallbak(method, version, args, callback) { /* 27 行 */ }
function myPostCallbakN(method, version, args, callback) { /* 20 行 */ }

// ✅ 改造后：1 行
var api = YfPlugin.createApi('mysql');

// 使用完全一致
api.post('get_db_list', {}, function(data) { renderList(data); });
api.postSilent('get_status', {}, function(data) { updateStatus(data); });
api.postCallback('backup_db', {name: 'test'}, function(data) { /* ... */ });
var result = await api.postAsync('get_db_info', {name: 'test'});
```

**收益**：
- 消除约 **3000+ 行**重复代码
- 错误处理行为统一（当前各插件的错误 shade 值不一致，有的是 `0.3`，有的是 `10`）
- `loading` 提示文本走 i18n 翻译
- 未来如需升级请求逻辑（如添加 CSRF Token、超时重试、请求队列），只需改一处

---

### 共用函数 2：`YfPlugin.parseArgs(args)` — 统一参数序列化

**问题**：部分插件使用 `toArrayObject(args)`，部分使用 `str2Obj(args)`，两者逻辑类似但实现不同。

```javascript
/**
 * 统一的参数序列化函数
 * @param {string|object} args
 * @returns {string} JSON 字符串
 */
YfPlugin.parseArgs = function(args) {
    if (typeof args === 'string') {
        return JSON.stringify(toArrayObject(args));
    }
    return JSON.stringify(args);
};
```

> 注：这个函数将被 `createApi` 内部调用，插件通常不需要直接使用。

---

### 共用函数 3：`YfPlugin.confirm(msg, onConfirm)` — 统一确认弹窗

**问题**：各插件的删除、重启等危险操作的确认弹窗样式和行为不统一。

```javascript
/**
 * 标准化的危险操作确认弹窗
 * @param {string} msg - 提示消息（支持 i18n key）
 * @param {function} onConfirm - 确认后的回调
 */
YfPlugin.confirm = function(msg, onConfirm) {
    var translatedMsg = (window.t && t(msg) !== msg) ? t(msg) : msg;
    layer.confirm(translatedMsg, {
        btn: [t('public.confirm') || '确认', t('public.cancel') || '取消'],
        icon: 0,
        title: t('public.warning') || '警告'
    }, function(index) {
        layer.close(index);
        if (typeof onConfirm === 'function') onConfirm();
    });
};
```

---

### 共用函数 4：`YfPlugin.renderInfoJson(pluginName, lang)` — info.json 多语言渲染

**问题**：面板核心在渲染软件列表时，直接读取 `info.json` 的 `title`/`ps`/`type` 中文字段。多语言化后需要一个统一的渲染层。

```javascript
/**
 * 获取插件 info.json 的多语言化展示信息
 * @param {string} pluginName
 * @returns {object} { title, ps, type } 已翻译的字段
 */
YfPlugin.getPluginInfo = function(pluginName) {
    var pt = YfI18n.createPluginTranslator(pluginName);
    return {
        title: pt('plugin_title'),
        ps: pt('plugin_ps'),
        type: pt('plugin_type')
    };
};
```

## 三、实施建议

### 文件位置

建议新建 `web/static/app/plugin_api.js`，独立于 `i18n.js`，在面板加载插件窗口时引入。

### 优先级排序

| 优先级 | 函数 | 影响范围 | 工作量 |
|--------|------|---------|--------|
| **P0** | `YfPlugin.createApi()` | 全部 41 个正式插件，消除 ~3000 行重复代码 | 中（编写框架 + 逐步迁移） |
| **P1** | `YfPlugin.parseArgs()` | 被 `createApi` 内部使用 | 低 |
| **P1** | i18n loading 文本（`createApi` 内调 `pt('loading')`） | 与 `createPluginTranslator` 联动 | 低 |
| **P2** | `YfPlugin.confirm()` | 涉及危险操作的插件 | 低 |
| **P2** | `YfPlugin.getPluginInfo()` | 面板核心软件列表渲染 | 低 |

### 兼容性策略

为了实现渐进式迁移，旧插件的 `myPost()` / `owPost()` 等函数暂时保留，新插件强制使用 `YfPlugin.createApi()`。在存量插件逐步改造 i18n 时同步替换。

## 四、后端（Python）共用函数需求

后端方面，`core/yf.py` 已经提供了较完善的基础设施（`returnJson`、`returnMsg`、`getInfo`、`readFile`、`writeFile`、`execShell` 等），**不需要**额外新增共用函数。

但有一个安全问题值得关注：扫描发现正式插件中仍有大量 **`os.system()` 直接拼接字符串执行命令** 的用法（`rsyncd`、`pureftp`、`php-apt`、`php-yum`、`mysql` 等），存在命令注入风险。建议在核心 `yf.py` 中补充一个 **安全的命令执行封装** 并在规范中要求统一调用：

```python
# core/yf.py 中建议新增
def safeExecShell(cmd_list):
    """安全的命令执行，使用列表参数避免注入"""
    import subprocess
    try:
        result = subprocess.run(cmd_list, capture_output=True, text=True, timeout=30)
        return result.stdout, result.returncode
    except Exception as e:
        return str(e), 1
```
