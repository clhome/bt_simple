# 插件转正检查单

> 适用范围：`文档/待审核插件/` 下的插件**搬进 `plugins/` 之前**必须逐项过一遍的审计单。
>
> 背景：转正的动作就是把文件**原样搬进 `plugins/` 直接进生产**（面板以 root 身份运行它们）。
> 而 `文档/待审核插件/` 里的存量代码长期在门禁之外 —— 已实测存在裸 `except`、
> `except Exception: pass`、`os.system` 拼串、裸 `yf.writeFile` 后直接报成功等形状。
> 所以「先纳入扫描」只是止血，**「转正必须过审计」才是出口**，本文件就是那个出口的载体。
>
> 用法：复制本文件为 `<插件名>-转正记录.md`，勾完并签上审计人后才能动 `plugins/`。
> 机械门禁（棘轮 / bandit / i18n / 严格模式）由 `python testsuite/run_all.py` 负责；
> 本清单负责**机械查不出来的那一半**，以及「查出来之后怎么改才是对的」。

---

## 0. 先跑机械门禁（结果贴进转正记录）

- [ ] `python scripts/verify_code_quality.py` 通过，且 `pending_*` 五项指标**不高于**
      `scripts/code_quality_baseline.json` 的现值（`bare_except` / `silent_except` /
      `print_in_web` / `os_system_count` / `writefile_bare_success`）
- [ ] `bandit -r <插件目录> -lll` **无 HIGH**（`-lll` 是阻断档；`-f json -o` 那份只出报告不阻断）
- [ ] 若插件用到 `yf.writeFile` / `yf.writeFileLog` 等写入原语，逐处确认
      **不是**「写完不看返回值就 `returnJson(True)`」（`writefile_bare_success` 口径）
- [ ] 六语言键齐全且**无死键**（`zh-CN` / `zh-TW` / `en` / `de` / `fr` / `it` 键集逐字对齐，
      `python scripts/verify_i18n.py` 通过）
- [ ] `pip-audit -r requirements.txt --strict` 不受本次转正影响（新增/改动依赖必须走依赖口径，见第 5 节）

## 1. 命令执行面（最高优先级）

- [ ] 全插件 `grep -n "os.system"` 为 0；残余必须逐条给出「为什么不能改」的理由并登记
- [ ] 所有命令构造优先 **argv 列表 + `shell=False`**（`execShellRc([...], shell=False)`）；
      `shell=True` 只允许出现在「需要内建/管道/重定向，且参数不含任何外部输入」的调用点，
      且**就地注释**说明理由
- [ ] 不存在裸拼命令字符串（用户可控值必须过 `yf.shlexQuote()`，或根本不进命令）
- [ ] 不存在 `eval` / `exec` 执行外部输入；`ast.literal_eval` 只用于**纯字面量**且已 `try/except` 兜底
- [ ] 口令 / 密钥 / Token **不进 argv、不进日志**（改 stdin：`--password-stdin`、`stdin_data=`）
- [ ] 每个「启停 / 安装 / 卸载」动作都判**真实退出码**，并在动作后**回读状态**
      （`systemctl` 返回 0 但进程没起来 → 必须如实报失败，不能假成功）

## 2. 路径与文件面

- [ ] 用户可控的文件名 / 目录名 / 站点名 / 用户名一律**白名单校验**（拒 `..`、`/`、控制字符、超长）
- [ ] 所有路径拼接后做 `realpath` / `normpath` 校验，必须落在允许根目录之内（堵目录穿越）
- [ ] 上传 / 解压：拒绝压缩包内的绝对路径与 `../`（Zip Slip），解压后核对落盘清单
- [ ] 权限与属主显式设定：目录 `755`（或按需 `1730`）、文件 `644`、可执行 `755`；
      **禁止 `chmod 777`**，也不允许 `chown` 到非服务账号
- [ ] 外部下载必须 **HTTPS + 校验和/签名**（固定版本 tag，不用 `master`/`latest` 分支快照），
      校验失败一律 `exit 1`（fail-closed），不得 `|| true` 跳过
- [ ] 删除/清理类动作的目标路径由**服务端固定推导**，不接受前端传入的任意路径

## 3. 安装 / 卸载脚本（`install.sh`）

- [ ] 进**严格模式**：`set -euo pipefail` + **ERR trap**（`trap ... ERR`，失败必须能定位到出错的命令，不静默）
- [ ] 引入共享规范库 `scripts/lib_install_report.sh`（`source` 后在结束时报安装结果，
      走统一的落账口径，而不是自己 `echo` 一句话）
- [ ] **显式动作分支**：`install|uninstall` 之外（无参 / 拼错 / 未知动作）一律 `exit 1`，
      不允许 `else` 兜底去跑卸载（历史上这类兜底会 `rm -rf` 掉安装目录）
- [ ] 新增的 `|| true` 为 **0**（`|| true` 是只减不增的棘轮项；确实可忽略的失败要写明理由）
- [ ] 版本号 / 参数走白名单（拒绝 `;`、空格、`/`、`..` 拼进下载 URL 或 `cd` 目标）
- [ ] 卸载后**回读确认**目录/服务/账号真的没了，再报成功

## 4. 危险版本口径

- [ ] 插件 `info.json` 的 `versions` 与《[组件生命周期与安全响应政策](组件生命周期与安全响应政策.md)》
      第 3 / 4 节口径一致：EOL 分支**默认下架**，确需使用必须显式「自担风险」放行
      （类 A 公网禁用、类 B 改走渠道包，两类文案不得混用）
- [ ] 若插件托管的是被政策覆盖的组件（PHP / MySQL / MariaDB / Nginx-OpenResty / Redis /
      PostgreSQL），安装脚本里的版本号与 sha256 必须与该政策登记的上游安全版一致
- [ ] 前端在用户选择 EOL 版本时有明确提示，且提示文案与后端的拒绝/放行语义一致

## 5. 依赖与锁口径

- [ ] 新增第三方依赖：`requirements.txt` 里必须有**带出处的版本区间**（下界取自实测版本），
      并在锁文件 / 例外清单里登记；不允许「无界依赖」静默出现
- [ ] 转正不引入新的 `python_version < '3.9'` 分档（该分档只用于面板自身兼容，
      不是插件逃避升级的通道）；相关 EOL 口径见政策文档第 8 节
- [ ] 系统级依赖（`apt` / `yum` 包）在脚本里显式安装并判失败，不假设目标机已有

## 6. 前端与国际化

- [ ] 所有输出到 DOM 的动态值经 HTML 转义、所有拼进 `onclick` 的实参经 JS 实参转义
      （存储型 XSS 是插件最常见的洞：插件名、站点名、备注、日志、容器名都算用户输入）
- [ ] 所有 `$.post` / `fetch` 都有 `.fail()`（500 时不能永久卡 loading 遮罩）
- [ ] 不做 `innerHTML` 拼接未转义内容；确需骨架模板时，动态片段必须已转义
- [ ] 六语言键集完全一致，无死键、无硬编码中文（`i18n` 静态门禁必须绿）

## 7. 转正动作本身（搬目录之后别漏）

- [ ] 插件目录从 `文档/待审核插件/` 移出到 `plugins/`，并在 `plugins/<name>/info.json` 补齐
      名称 / 版本 / 作者 / 说明
- [ ] **同步 36 插件契约计数**：`testsuite/test_repo_contract.py` 的
      `EXPECTED_PLUGIN_COUNT` 与 `testsuite/test_plugin_i18n_complete.py` 里写死的
      **36** 都要跟着 +1（两处写死，只改一处必红）
- [ ] 同步 `testsuite/test_pending_plugins_scan_scope.py` 的 `pending_*` 基线 +
      `scripts/code_quality_baseline.json`（转正后待审核段实测值会变，**只降不升**）
- [ ] 若该插件此前被 `web/utils/plugin.py` 的「待审核」逻辑排除，转正后确认它已出现在插件列表里
- [ ] `python testsuite/run_all.py` 全绿（含 4 项静态门禁），再提交
