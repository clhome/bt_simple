## 1. 载体拓扑（先看清有哪几个真源）

每语言 13 个载体，但**只有 3 类是独立真源**，其余是派生：

```
web/static/language/<lang>/
├── lan.js                  ← 前端真源（innerHTML，保留 <p>/<br>）
├── public.json             ← 后端扁平真源（禁含 HTML）
├── template.<menu>.json ×9 ← 后端分片真源（禁含 HTML）
├── template.json           ← 【派生】9 分片的并集，兼容垫片
└── log.json                ← 独立小载体（本次不动）
```

消费方**只有 2 处**（已全量核查）：

| 消费方 | 位置 | 读什么 |
|--------|------|--------|
| 后端 | `web/core/i18n.py::_lookup_message` | `public.json` → `server.json` → 分片 |
| 前端 | `web/static/app/i18n.js::loadMenuLan` | 分片（`/static/language/<lang>/template.<menu>.json`） |

## 2. 事实与证据

### 2.1 分歧规模（按 `(section, key)` 精确匹配）

> 方法学坑：第一版脚本按**裸键名**匹配，得到 5371 条虚高数据 —— 因为同名键会出现在
> 多个 section（`are_you_sure_you_1` 在 `zh-CN/lan.js` 里出现 **5 次**，值各不相同）。
> 必须按 `(section, key)` 匹配。

```
三载体同条目分歧：共 2161 条
  CONTENT   1709   zh-TW 572 / it 324 / en 323 / de 234 / fr 199 / zh-CN 57
  SEP_ONLY    17   剥标签丢分隔符（上一轮已修 12 处，余下多为空白噪声）
  WS_ONLY    435   仅空白归一差异（非缺陷）
```

分歧最集中的载体对：

| 载体对 | 条数 |
|--------|------|
| `lan.js[index]` ↔ `template.index.json[index]` | 343 |
| `lan.js[crontab]` ↔ `template.crontab.json[crontab]` | 330 |
| `lan.js[site]` ↔ `template.site.json[site]` | 320 |
| **`template.setting.json[public]` ↔ `public.json`** | **109** |

最后一行是**结构性缺陷**：同一个逻辑 section（`public`）在后端有**两个载体**。

### 2.2 后端对同一个串会取到两个不同的值

`_lookup_message(key, lang)` 的真实顺序（`web/core/i18n.py:256`）：

1. `public.json`（**扁平键**优先命中）
2. `server.json`
3. 分片：`sec.sub` → `template.<SECTION_TO_MENU[sec]>.json[sec][sub]`

于是：

| 调用形式 | 命中 | en 取值 |
|----------|------|---------|
| `t('retrieving_configuration_template')` | `public.json` | `Retrieving configuration template...` ✅ |
| `t('public.retrieving_configuration_template')` | `template.setting.json[public]` | `configurationFetching template...` ❌ |

同一个字符串，**换个寻址方式就换个值**。这就是 §4 那张表里「一侧正确、一侧乱码」的机制。

活键实测（`yf.returnData(False, 'setting.py_msg_448940')` → 后端 `t()` → 分片）：

| 键 | 后端（用户看到） | 前端（lan.js） |
|----|------------------|----------------|
| `setting.py_msg_448940` | `tryautomaticInstallACMEfailed,Please try with the following commandmanualInstall...` ❌ | 同乱码 ❌ |
| `site.import_result_msg` | `...{1} sitesSkipped: {2} sites` ❌ | `...{1} sites<br>Skipped: {2} sites` ✅ |
| `public.kill_all_php_processes` | `killall phpprocess` ❌ | `Kill all PHP processes` ✅ |
| `public.forcibly_terminates_and_restarts` | `:forceTerminate and restart allprocess...` ❌ | `: Forcibly terminates and restarts...` ✅ |
| `public.retrieving_profile_path` | 乱码（后端从不调用） | `None` → 前端退到硬编码中文 ⚠️ |

### 2.3 根因：**两套流水线、两套基线**（git 考古）

```
553a16543  2026-08-29  整体翻译            （这些键还不存在）
719132394  2026-09-07  en翻译补全          ← 乱码首次出现，只在 en/template.json
4d4051205  2026-09-10  安全性、可靠、性能加固，语言完整
                                           ← public.json 写入【正确】值，
                                             template.json 的乱码【保留不动】
036e676ad  2026-09-10  优化翻译            ← 仍未修
```

复现命令：

```bash
git log --oneline -S 'configurationFetching template' -- web/static/language/en/
git show 719132394:web/static/language/en/template.json | grep -n configurationFetching
git show 4d4051205:web/static/language/en/public.json  | grep -n kill_all_php_processes
```

两条独立的生成链：

| 链 | 工具 | 产物 | 质量来源 |
|----|------|------|----------|
| A | `build_all_languages.py` / `restore_and_build_high_quality_i18n.py` | `lan.js`、`public.json`、`template.json` | 策展字典 `FULL_I18N_DICTIONARY` + 基线 |
| B | 更早的机翻脚本（已不在仓库） | 分片 | **glossary 逐词 `str.replace` 拼接** |

**机制已验证**（glossary 无空格处理）：

```python
# test/i18n_scripts/tools/build_all_languages.py::translate_text 的兜底分支
for zh, trans in CORE_PHRASES.items():
    if zh in res and target_lang in trans:
        res = res.replace(zh, trans[target_lang])
```

实测：`kill所有php进程` → `kill所有phpProcess`（当前词表）；出货版本是 `killall phpprocess`
（同一机制、更全的旧词表）。同族指纹：`tryautomaticInstallACMEfailed`、`configurationFetching`、
`sitesSkipped`、`manualInstall`、`forceTerminate`、`logpathFetching`。

**并且「高质量构建器」把两套基线都固化了下来**：

```python
# restore_and_build_high_quality_i18n.py
final_template[sec] = merge_section_data(target, zh_sec, base_template[sec], full_sec)   # 基线 = 旧 template.json
final_sections[sec] = merge_section_data(target, zh_sec, base_sections[sec], full_sec)   # 基线 = 旧 lan.js
```

两条链各读**自己的**基线（都取自 553a16543），且叶子优先级是
`FULL_I18N_DICTIONARY > base > convert_tw > zh_val`。
⇒ **凡未被策展字典覆盖的键，两侧被永久冻结在各自的历史值上，结构上不可能收敛。**
末位兜底是 `zh_val`（原样中文），这也解释了 171 键 × 4 语言的漏译。

### 2.4 前端分片合并是个空操作（附带发现）

```js
// web/static/app/i18n.js:900
for (var k in data) {
    if (hasOwnProperty.call(data, k) && !(k in window.lan)) {   // ← 条件
        window.lan[k] = data[k];
    }
}
```

分片的**顶层键就是 section 名**（`config`/`public`/`site`/…），而 `lan.js` 已定义同名 section
⇒ 条件恒假 ⇒ **整段被跳过**。实测：

```
分片总数 54
顶层键全部已被 lan.js 覆盖 ⇒ 合并整段无效: 36   （site/security/monitor/logs/soft/setting ×6 语言）
部分有效: 18                                   （index/files/crontab，因为带了 MENU_FLAT 扁平键）
```

结论：**前端对 section 键只读 `lan.js`**。所以那 1709 条 CONTENT 分歧里，
落在分片上的那些对前端是**不可见**的 —— 但对后端可见（§2.2）。

## 3. 收敛方案

### 3.1 推荐方案 A：`lan.js` 单源 + 派生载体 + 派生守卫

**为什么以 `lan.js` 为源**（不是 `.json`）：

| 判据 | `lan.js` | `.json` |
|------|----------|---------|
| 能否表达 `<br>` 语义 | ✅ innerHTML | ❌ 红线禁含 HTML |
| 覆盖分片条目 | **9 分片中 6 个 100% 覆盖**（crontab/files/site/security + 2）；index/logs/monitor 各缺 1 条；setting 缺 116、soft 缺 77 ⇒ 共 196 条 | — |
| 覆盖 `public.json` | 交集 512；仅 `public.json` 有 75 条、仅 `lan.js` 有 20 条 | — |
| 前端唯一实际生效的载体 | ✅（§2.4） | ❌ |
| zh-TW 925 条手工翻译所在 | ✅ | ❌ |

**收敛动作只有三步：**

#### A1 把 196 个「仅存在于分片」的键一次性并入 `lan.js`

各语言都是 **196 条**（6 语言完全一致，说明两侧共享同一键骨架）。其中 **91 条在 `web/` 里有引用点**：

- `plugins.<name>.title` / `plugins.<name>.ps` ×65 —— **插件简介，必须保留**（lan.js 完全没有）
- `public.save_1` / `refresh_1` / `edit_online` / `auto_refresh` / `tip_use_ctrl_to` … —— 多为
  遗留重复键，值本身也是 glue（`'Now save,Please wait...'`、`'automaticrefresh'`），逐条定夺
- `menu.crontab`、`control.pre`、`soft.management_action`、`logs.logaudittable_position_relative_block`

> 反向也要看一眼：`lan.js` 有而分片缺 **696 条**，其中仅 **8 条**有引用点
> （`public.management_action`、`public.pre`、`public.boot_start*`、`public.setting_boot_start`）——
> 这 8 条顺带补进分片。

#### A2 新增导出器：`lan.js → public.json + template.<menu>.json + template.json`

核心变换（**这就是「优雅」的落点** —— 把原先手搓、且做错的剥标签，换成一条确定规则）：

```python
def to_carrier(lan_value):
    """lan.js 走 innerHTML，标签是【分隔符】；.json 载体禁含 HTML。
    因此标签必须换成空格，而不是删空。"""
    v = re.sub(r'<[^>]*>', ' ', lan_value)   # ← 关键：' ' 而不是 ''
    v = re.sub(r'[ \t]+', ' ', v).strip()
    assert not re.search(r'<[a-zA-Z][^>]*>', v), v   # 复用既有红线
    return v
```

这一个函数**同时**修好 §4 的两类：

- `SEP_ONLY`（`手动安装` + `<p>` + `安装命令` → `安裝安裝命令`）：不再需要 `test/fix_lang_glue.py` 那种外科补丁
- `import_result_msg`：`...{1} sites<br>Skipped: {2} sites` → `...{1} sites Skipped: {2} sites`
  （正好就是 §4 里标注「应为 `sites Skipped`」的那条）

分片归属沿用 `merge_template_by_menu.py` 的 `MENU_SECTIONS` + `MENU_FLAT`
（`MENU_FLAT` 那批扁平键必须挂在分片**顶层**，否则 `_lookup_message` 的扁平键路径失效）。

**改动面（干跑实测）：**

| 语言 | 分片条目 | 值变化 | 值不变 | 将丢失 |
|------|---------|--------|--------|--------|
| zh-CN | 4224 | 114 | 3914 | 196 |
| zh-TW | 4224 | 588 | 3440 | 196 |
| en | 4224 | 398 | 3630 | 196 |
| fr | 4224 | 251 | 3777 | 196 |
| de | 4224 | 284 | 3744 | 196 |
| it | 4224 | 314 | 3714 | 196 |
| **合计** | **25344** | **1949 (7.7%)** | **22219 (87.7%)** | **1176** |

「将丢失」全部由 A1 预先并入消解。

#### A3 新增守卫：**载体可复现**（把「两真源」变成「一真源 + 已证明同步的派生」）

这是本方案最强的一环 —— 一个**自证型**不变量：

```
testsuite/test_lang_carrier_derivation.py
  用例：在内存里用 to_carrier() 从 lan.js 重导一遍，
        与磁盘上的 public.json / template.<menu>.json / template.json
        做规范化 JSON 逐字节比对，必须完全一致。
```

- 任何人手改 `.json` 而没改 `lan.js` ⇒ 门禁立刻红，并精确报出键名。
- **必须做变异自证**（否则是真空通过）：把某个分片值改一个字，守卫必须报红。
- 与既有 `testsuite/test_lang_pack_integrity.py` 互补：后者守「术语自我复制 / 相邻重复」，
  本守卫守「载体是否还是派生物」。两者都需要**自带 oracle**（不得 import `test/`）。

> 注：`testsuite/` 会被提交，`test/` 被 gitignore 且契约守卫
> `test_repo_contract.py` 禁止引用 —— 所以导出器的 `to_carrier()` 必须**复制一份**进
> `testsuite/`（或提升为 `scripts/tools/` 下的生产脚本，由两处共同引用）。
> 推荐后者：`scripts/tools/export_lang_carriers.py`，`testsuite/` 只做「重导 + 比对」。

#### A4 删掉前端分片拉取

收敛后分片内容 ⊂ `lan.js`，`loadMenuLan` 对 section 键**永远无效**（§2.4），
对扁平键也已由 A1 并入 `lan.js`。删除后：

- 每页省一次 `/static/language/<lang>/template.<menu>.json` 请求
- 少一条「合并条件写错」的暗雷（`_MENU_LOADED` / `_MENU_QUEUE` / `PATH_TO_MENU` 一并清理）

**分片文件本身要保留** —— 后端 Python 仍要读。

#### A5 翻译质量单独立单（因为只有一个源，改一次到处生效）

用 `test/i18n_user_visible_damage.py` 枚举（只统计 `web/` 里**有引用点**的键）：

```
用户可见损坏：共 896 条（en/de/fr/it）
  GLUE   de 119 / en 84 / fr 5 / it 4      ← glossary 逐词拼接
  EMPTY  en/de/fr/it 各 171                ← 纯漏译，模板只能退到硬编码中文
```

GLUE 判定器（已白名单化，放过 `BasicAuth`/`JavaScript` 这类合法标识符）：

```python
GLUE = re.compile(r'(?<![A-Za-z])[a-z][a-z0-9]*[A-Z][a-z]')
```

样例：

| 键 | 语言 | 现状 |
|----|------|------|
| `config.if_you_forget_your` | en | `If forgotten, password,can be SSHpassbscommand to closeBasicAuthverify` |
| `config.day_free_certificate_application` | en | `90dayfreeCertificateapplysuccessful` |
| `config.once_enabled_any_attempt` | de | `Nach der Aktivierung ... Eingabe vonBasicAuthBenutzername und Pa...` |
| `admin.py_msg_4adbdf` | de | `AuflösenImportierenDaten fehlgeschlagen: {1}` |
| `config.change_password` | it | `ModificaPassword` |

`EMPTY` 那 171 键（`config.compress`、`config.checking_backup`、`config.btn_confirm_import` …）
在 `lan.js` 与分片里**都不存在**，模板靠 `{{ t("config.compress", "压缩") }}` 退到中文 ——
这是**翻译覆盖缺口**，与「机翻损坏」是两件事，建议单开一单（不影响本方案落地）。

### 3.2 为什么不选 B：把 `.json` 当权威

1. `.json` 不能含 HTML ⇒ 表达不了 `<br>`，而前端 `site.import_result_msg` 等键依赖它
   （`<br>` 在 `lan.js` 里是真实换行）。
2. 反向迁移会丢 **696 条** `lan.js` 独有键（其中 8 条有引用点）。
3. `.json` 正是被机翻污染更重的一侧。

### 3.3 为什么不选 C：后端直接读 `lan.js`

理论上最彻底（零派生），但 Python 侧要解析 JS 对象字面量：要么运行时依赖 node
（`restore_and_build_high_quality_i18n.parse_lan_js` 就是这么干的），要么自写容错解析器。
**为省掉一个派生步骤而给面板运行时引入新的解析风险，不划算**；A2+A3 已能达到
「单一真源 + 已证明同步」同等强度，且风险留在构建期。

### 3.4 残余人工量（收敛之后）

| 项 | 量 | 性质 |
|----|----|------|
| A1 并入 196 键（×6 语言） | 1176 条 | 机械搬运 + 91 条逐条定夺 |
| GLUE 重译 | 212 条（en 84 / de 119 / fr 5 / it 4） | 人工翻译 |
| EMPTY 补译 | 684 条（171 键 × 4 语言） | 人工翻译，可另立单 |
| `处理程序` / `處理程式` 用词统一 | 见上游 §5.1 | 产品定夺 |

## 4. 实施顺序与回滚

```
①  A1 并入 196 键          → 只增不改，git diff 可逐条审；此时门禁应全绿
②  A2 导出器（--dry-run 默认）→ 产出 1949 条 diff 报告，人工过一遍
③  A2 --apply              → 生成 .json 载体
④  A3 守卫 + 变异自证      → 加进 testsuite
⑤  A4 删前端分片拉取       → 独立提交，便于回滚
⑥  A5 GLUE 重译            → 单独立单
```

回滚：①②③ 全是**语言包数据 + 一个工具**，`git revert` 单个提交即可；
④⑤ 互相独立。**不涉及后端/前端运行时逻辑改动**（除 ⑤ 的删除）。
