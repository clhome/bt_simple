# 御风面板 - 插件统一开发规范 v2.0

为了确保御风面板（bt_simple）的插件体系具备高度的 **稳定性、可靠性、安全性与高效率**，同时为国际化（i18n）改造及后续新插件开发提供可执行的标准依据，特制定本规范。

所有新插件的开发及存量插件的重构 **均需严格遵循本规范**。

---

## 1. 核心设计原则

- **KISS 原则**：插件设计应尽量保持精简，避免过度设计和引入不必要的外部依赖。
- **高内聚低耦合**：插件的所有资源（配置、脚本、前端、语言包等）必须完全内聚在插件所属目录下，严禁跨界污染面板核心文件。
- **统一编码规范**：所有代码文件（包括 Python、Shell、JS、HTML、JSON）**强制统一使用 UTF-8 (无 BOM)**，换行符强制使用 **LF**（`\n`）。
- **禁止重复造轮子**：面板核心 `core/yf.py` 中已封装的常用方法（文件读写、权限修改、服务管理等），插件 **必须直接调用**，禁止在插件目录下重新实现。

---

## 2. 标准插件目录结构

每个插件必须遵循以下标准目录骨架：

```
plugins/<plugin_name>/
├── info.json              # [必须] 插件元数据声明（见第 3 节）
├── index.py               # [必须] 后端入口（Python）
├── index.html             # [必须] 前端入口页面
├── install.sh             # [必须] 安装/卸载/更新脚本（见第 8 节）
├── ico.png / ico.svg      # [必须] 插件图标（优先 SVG）
├── js/
│   └── <plugin_name>.js   # [必须] 前端业务逻辑
├── lang/                  # [必须] 多语言目录（见第 4 节）
│   ├── zh-CN.json         #   简体中文
│   ├── en.json            #   英文
│   └── ...                #   其他支持语言（zh-TW, fr, de, it）
├── conf/                  # [可选] 配置文件模板
├── init.d/                # [可选] Systemd/init 服务模板
├── scripts/               # [可选] 辅助脚本
├── README.md              # [建议] 插件说明文档
└── task.md                # [建议] 迭代任务记录
```

**命名约定**：

| 项目 | 规范 |
|------|------|
| 插件目录名 | 全小写，下划线分隔（如 `op_waf`、`task_manager`） |
| JS 文件名 | 与插件目录名一致（如 `op_waf.js`） |
| lang 文件名 | 使用语言代码（如 `zh-CN.json`、`en.json`） |

## 3. info.json 元数据规范

`info.json` 是面板加载和展示插件的唯一入口声明文件，必须严格遵循以下 Schema。

### 3.1 完整字段定义

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `name` | string | ✅ | 插件唯一标识（全小写，与目录名一致） |
| `title` | string | ✅ | 插件显示名称（**仅用于 i18n key 的回退**，最终展示由语言包决定） |
| `ps` | string | ✅ | 插件简要描述（**回退文本**，最终展示由语言包决定） |
| `type` | string | ✅ | 插件分类，必须使用枚举值（见下方） |
| `sort` | number | ✅ | 软件列表排序权重（数值越小越靠前） |
| `versions` | string[] | ✅ | 支持的版本列表 |
| `shell` | string | ✅ | 安装脚本文件名（通常为 `install.sh`） |
| `checks` | string | ✅ | 安装检测路径（相对于 `/www/server/`） |
| `path` | string | ✅ | 软件安装路径（相对于 `/www/server/`） |
| `tip` | string | ✅ | 软件分区标识：固定值 `"soft"` |
| `display` | number | ✅ | 展示模式：`0` 不显示, `1` 首页, `2` 软件列表 |
| `author` | string | ✅ | 作者/开发组织 |
| `home` | string | ✅ | 官方主页 URL |
| `date` | string | ✅ | 最后更新日期（`YYYY-MM-DD`） |
| `pid` | string | ✅ | 进程类型标识：`"1"` Web, `"2"` 数据库, `"6"` 语言 |
| `coexist` | boolean | ⬜ | 是否允许多版本共存（默认 `false`） |
| `install_pre_inspection` | boolean | ⬜ | 安装前是否进行环境检查 |
| `uninstall_pre_inspection` | boolean | ⬜ | 卸载前是否进行确认检查 |
| `hook` | array | ⬜ | 钩子注册（如站点回调） |
| `size` | string[] | ⬜ | 弹窗尺寸 `[宽, 高]`（单位 px） |
| `todo_versions` | string[] | ⬜ | 待开发版本列表（仅内部参考） |

### 3.2 type 字段枚举

`type` 字段**不允许**使用自由文本，必须从以下枚举中选取：

| 枚举值 | 说明 |
|--------|------|
| `"web_server"` | Web 服务器（如 OpenResty、Apache、Caddy） |
| `"database"` | 数据库（如 MySQL、MariaDB、PostgreSQL、MongoDB） |
| `"cache"` | 缓存/KV 数据库（如 Redis、Valkey） |
| `"language"` | 编程语言运行时（如 PHP、Python、JDK） |
| `"security"` | 安全防护（如 OP 防火墙、Fail2ban、防篡改） |
| `"tool"` | 系统工具（如 Supervisor、Swap、系统优化） |
| `"ftp"` | FTP 服务（如 PureFTP） |
| `"admin"` | 管理工具（如 phpMyAdmin、pgAdmin） |
| `"container"` | 容器服务（如 Docker） |
| `"other"` | 其他插件 |

> ⚠️ **存量插件迁移**：当前存在 `"运行环境"`、`"其他插件"`、`"PHP语言解释器"` 等不规范中文值和数字 `0`，需要统一迁移到枚举值。面板核心的软件列表渲染代码需配套兼容处理。

## 4. 国际化 (i18n) 规范

### 4.1 系统 i18n 架构概览

面板已有完整的双端 i18n 基础设施：

| 层级 | 组件 | 位置 | 作用 |
|------|------|------|------|
| 前端引擎 | `YfI18n` | `web/static/app/i18n.js` | 提供 `window.t(key)` 翻译函数和 `data-i18n` DOM 自动翻译 |
| 后端引擎 | `core.i18n` | `web/core/i18n.py` | 提供 `t(key, *args)` 翻译函数，支持点号查找和多词典回退 |
| 核心辅助 | `yf.returnJson()` | `web/core/yf.py` | 自动调用 `core.i18n.t()` 翻译 `msg` 参数 |
| 核心辅助 | `yf.returnMsg()` | `web/core/yf.py` | 通过 `public.json` 词典查找并翻译消息 |
| 语言文件 | `lan.js`, `public.json`, `template.json` | `web/static/language/<code>/` | 面板核心的多语言词典 |

**插件的 i18n 需要在此基础设施之上，增加插件级的语言包文件。**

### 4.3 前端 i18n 改造标准

#### 4.3.1 插件 JS 加载语言包

在插件的主 JS 文件顶部，新增异步加载插件专属语言包的逻辑：

```javascript
// plugins/op_waf/js/op_waf.js

// 插件语言包（在全局注册到 window.pluginLang 命名空间）
var _pluginLang = {};

(function loadPluginLang() {
    var lang = (window.YfI18n && YfI18n.getCurrentLang()) || 'zh-CN';
    $.ajax({
        url: '/plugins/file?name=op_waf&f=lang/' + lang + '.json',
        dataType: 'json',
        async: false, // 必须同步，确保后续代码能取到翻译
        success: function(data) { _pluginLang = data || {}; },
        error: function() {
            // 回退到中文
            $.ajax({
                url: '/plugins/file?name=op_waf&f=lang/zh-CN.json',
                dataType: 'json',
                async: false,
                success: function(data) { _pluginLang = data || {}; }
            });
        }
    });
})();

/**
 * 插件级翻译函数
 * @param {string} key - 语言包中的 key
 * @param  {...any} args - 替换参数 {1}, {2}...
 * @returns {string}
 */
function pt(key) {
    var msg = _pluginLang[key] || key;
    for (var i = 1; i < arguments.length; i++) {
        msg = msg.replace('{' + i + '}', arguments[i]);
    }
    return msg;
}
```

#### 4.3.2 JS 代码中使用翻译

```javascript
// ❌ 禁止：硬编码中文
var loadT = layer.msg('正在获取...', { icon: 16, time: 0, shade: 0.3 });

// ✅ 正确：使用插件翻译函数
var loadT = layer.msg(pt('loading'), { icon: 16, time: 0, shade: 0.3 });
```

```javascript
// ❌ 禁止：标题硬编码
layer.open({
    title: "设置响应代码【" + ruleName + "】",
});

// ✅ 正确：参数化翻译
layer.open({
    title: pt('set_response_code', ruleName),
});
```

#### 4.3.3 HTML 菜单的标准写法

```html
<!-- ❌ 禁止：硬编码中文 -->
<p class="bgw" onclick="renderWafService();">服务</p>
<p onclick="wafScreen();">首页</p>

<!-- ✅ 正确：使用 data-i18n 属性（由 i18n.js 引擎自动翻译） -->

<p onclick="wafScreen();" data-i18n="plugin.op_waf.menu_index">首页</p>
```

> 注意：HTML 中保留中文原文作为回退值。`data-i18n` 的值将由 `i18n.js` 引擎在 DOM 加载后自动翻译。如果 key 未匹配到翻译，则保持原始文本不变。

### 4.4 后端 i18n 改造标准

#### 4.4.1 使用 `yf.returnJson()` 的自动翻译

`yf.returnJson()` 已经内置了 `core.i18n.t()` 的自动调用，因此只要传入的 `msg` 是在 `public.json` 或 `template.json` 中已注册的 key，就会自动翻译。

```python
# ✅ 最佳方式：使用 public.json 中已有的通用 key
return yf.returnJson(True, 'SET_SUCCESS')   # → "设置成功" / "Settings saved"
return yf.returnJson(False, 'ARGS_ERR')     # → "指定参数无效!" / "Invalid arguments!"
```

#### 4.4.2 携带参数的消息

```python
# ✅ 使用 yf.getInfo() 进行参数替换（保持向后兼容）
return yf.returnJson(True, yf.getInfo('修改数据库[{1}]密码成功!', (name,)))
```

#### 4.4.3 禁止的做法

```python
# ❌ 禁止：直接硬编码长篇中文消息
return yf.returnJson(False, '数据库连接失败,请检查数据库服务是否启动!')
return yf.returnJson(False, '与当前存储目录相同，无法迁移文件!')
return yf.returnJson(True, '清理BINLOG成功!')

# ✅ 应改为使用 public.json 中的 key 或注册新 key
return yf.returnJson(False, 'MYSQL_CONN_FAIL')
return yf.returnJson(False, 'MYSQL_SAME_DIR')
return yf.returnJson(True, 'MYSQL_BINLOG_CLEAN_OK')
```

## 5. 安全性规范

### 5.1 严格的输入校验

**绝不信任前端传递的数据**。所有 API 参数必须经过类型验证、长度验证和字符白名单过滤。

```python
# ✅ 好的做法：输入校验函数
def safe_check_args(db_name=None, sign_val=None, username=None):
    if db_name is not None:
        if not re.match(r"^[a-zA-Z0-9_-]+$", db_name):
            return False
    if sign_val is not None:
        if not re.match(r"^[a-zA-Z0-9_\-\.:]+$", sign_val):
            return False
    if username is not None:
        if not re.match(r"^[a-zA-Z0-9_-]+$", username):
            return False
    return True
```

### 5.2 防范命令注入

```python
# ❌ 禁止：字符串拼接执行命令
os.system("rm -rf /www/server/" + user_input)

# ✅ 正确：使用安全的参数化调用
subprocess.run(["rm", "-rf", safe_path], check=True)

# ✅ 更优：使用 Python 原生模块
import shutil
shutil.rmtree(safe_path)
```

### 5.3 防范路径穿越

```python
# ✅ 路径安全校验
def validate_path(target_path, allowed_base="/www/wwwroot/"):
    real_path = os.path.realpath(target_path)
    if not real_path.startswith(os.path.realpath(allowed_base)):
        return False
    return True
```

### 5.4 最小权限原则

- 安装脚本中 **严禁** 对系统关键目录使用 `chmod 777`
- 配置文件权限：`644`
- 可执行文件权限：`755`
- 敏感文件（密钥等）：`600` 或 `400`

## 6. 稳定性与可靠性规范

### 6.1 全面的异常处理

所有后端 API 方法必须捕获异常，返回标准 JSON 格式，**绝对不能导致面板后端崩溃**。

```python
def some_api_method():
    try:
        # 业务逻辑
        result = do_something()
        return yf.returnJson(True, 'SUCCESS', result)
    except Exception as e:
        return yf.returnJson(False, str(e))
```

### 6.2 健壮的安装与卸载

- **幂等性**：安装脚本必须支持重复执行而不破坏已有配置
- **优雅失败**：安装中途失败时，应清理已创建的残留文件和目录
- **卸载无残留**：清理定时任务、Systemd 服务文件、二进制文件，**但默认保留用户数据**

### 6.3 守护进程规范

需要长时间驻留后台的服务型插件，必须通过 Systemd 进行进程守护，并配置自动重启：

```ini
[Service]
Restart=always
RestartSec=3
```

## 7. 性能规范

### 7.1 避免阻塞面板主进程

超过 **3 秒** 的长耗时任务（源码编译、大数据查询、日志大范围分析等），**严禁在 HTTP 响应周期内同步执行**。必须改用后台异步任务并让前端轮询进度。

### 7.2 严控 I/O 与内存

- 大文件（日志等）读取 **严禁** 一次性 `read()` 到内存，必须使用迭代器/生成器或 `seek + tail` 技术
- 高频接口应引入内存缓存机制

### 7.3 资源泄漏防范

```python
# ✅ 后端：使用上下文管理器确保资源安全关闭
with open(filepath, 'r', encoding='utf-8') as f:
    content = f.read()
```

```javascript
// ✅ 前端：窗口关闭时销毁定时器，防止内存泄漏
var timer = setInterval(function() { /* 轮询逻辑 */ }, 3000);

// 在关闭窗口时
layer.open({
    cancel: function() { clearInterval(timer); }
});
```

## 8. install.sh 安装脚本规范

### 8.1 标准入参约定

| 参数 | 变量 | 说明 |
|------|------|------|
| `$1` | `action` | 操作类型：`install` / `uninstall` / `update` |
| `$2` | `type` | 版本号（如 `8.0`、`1.5`） |

### 8.2 标准脚本模板

```bash
#!/bin/bash
PATH=/bin:/sbin:/usr/bin:/usr/sbin:/usr/local/bin:/usr/local/sbin:~/bin
export PATH

# ---- 路径初始化（必须） ----
PLUGIN_PATH=$(cd "$(dirname "${BASH_SOURCE[0]}")"; pwd)
curPath=${PLUGIN_PATH}
rootPath=$(dirname "$curPath")
rootPath=$(dirname "$rootPath")
serverPath=$(dirname "$rootPath")

# lib.sh 可能改变 curPath，必须恢复
```

## 9. 版本管理与兼容性

### 9.1 版本号规范

插件版本使用 **语义化版本号**（Semantic Versioning）：`MAJOR.MINOR.PATCH`

| 变更类型 | 版本号变化 | 示例 |
|----------|-----------|------|
| 不兼容的 API 变更 | MAJOR +1 | `1.0.0` → `2.0.0` |
| 向后兼容的新功能 | MINOR +1 | `1.0.0` → `1.1.0` |
| 向后兼容的缺陷修复 | PATCH +1 | `1.0.0` → `1.0.1` |

### 9.2 依赖声明

如果插件依赖其他软件（如 `op_waf` 依赖 `openresty`），应在 `info.json` 中通过 `depends` 字段声明（未来面板核心需要配套支持）：

```json
{
    "depends": ["openresty"]
}
```

### 9.3 升级数据迁移

插件升级时，如果涉及数据结构变更（如数据库表结构、配置文件格式变化），应在 `index.py` 中实现版本检测和自动迁移逻辑。

## 10. 代码结构与重用

### 10.1 统一的 API 返回格式

所有后端 API 的返回必须遵循以下标准 JSON 结构：

```json
{
    "status": true,
    "msg": "操作成功",
    "data": { ... }
}
```

- `status`：布尔值，`true` 表示成功，`false` 表示失败
- `msg`：提示消息（经过 i18n 翻译后的文本）
- `data`：可选，返回的业务数据

### 10.2 文档与注释

- 各插件的复杂逻辑（正则匹配、底层调用、网络请求等）必须包含清晰准确的注释
- 插件根目录应配套 `README.md`，记录配置项说明和使用方式
- 建议维护 `task.md`，记录版本迭代和待办事项
