# 御风面板 - 插件升级与改造日志

此文档用于记录面板核心系统以及各插件在升级与多语言（i18n）改造过程中的重要变更、决策和踩坑记录。

## 2026-08-28：核心引擎支持插件专属 i18n 工厂函数

**背景**：
在制定《插件统一开发规范 v2.0》时发现，如果要求面板存量的 42 个插件在前端独立加载语言包，每个插件都会在其 JS 文件顶部充斥多达几十行的 Ajax 同步加载和参数替换函数，导致极大的代码冗余，且不利于后续缓存机制的统一升级。

**改造内容**：
- **核心框架升级**：在 `web/static/app/i18n.js` 中新增了 `YfI18n.createPluginTranslator(pluginName)` 工厂函数。
- **机制说明**：该函数内部维护了 `_pluginDicts` 全局字典进行按插件名的缓存。在调用时会同步阻塞去请求 `/plugins/file?name=xxx&f=lang/<lang>.json`，如果当前语言包不存在，则自动回退加载 `zh-CN.json`。
- **插件端简化**：插件的 `js/xxx.js` 前端逻辑只需使用以下单行代码即可完成 i18n 的初始化和绑定，返回一个完全绑定了当前插件作用域的 `pt(key, ...args)` 闭包。

```javascript
var pt = YfI18n.createPluginTranslator('插件目录名');
```

**影响评估**：
此举极大地简化了所有存量插件的 i18n 改造难度，消除了重复代码，提升了长期可维护性。后续开始改造诸如 `op_waf`、`mysql` 等插件时，将直接采用这种极简方式。

## 2026-08-28：建立前端安全共用 API 封装与后端防注入调用

**背景**：
在多语言改造的扫描中发现，原 41 个插件不仅重复定义了冗长的 `xxxPost()` 请求函数，且大部分后端存在使用 `os.system()` 拼接字符串执行系统命令的安全隐患。为了统一错误处理、为后续防 CSRF 等安全策略做准备，并根除 Shell 注入漏洞，对核心层做了补充。

**改造内容**：
- **前端核心扩展**：新建了 `web/static/app/plugin_api.js` 并全局引入（在 `layout.html` 和 `login.html`）。暴露了 `YfPlugin` 命名空间。
- **前端规范更新**：所有插件的前端 API 调用，废弃 `myPost()` 等自定义函数，统一使用 `var api = YfPlugin.createApi(pluginName)` 获取实例，通过 `api.post()`, `api.postSilent()`, `api.postAsync()` 进行请求。
- **全局基础功能**：封装了 `YfPlugin.confirm()` 标准危险操作确认弹窗，及 `YfPlugin.getPluginInfo()` 用于列表的多语言信息渲染。
- **后端防注入封装**：在 `web/core/yf.py` 中新增 `safeExecShell(cmd_list)`，要求所有系统命令必须以列表（List）形式传入以绕过 Shell 解释器，彻底根除注入风险。
- **规范同步**：《插件统一开发规范 v2.0》已同步补充上述标准。
## 2026-08-28：op_waf (第一阶段试点) 改造完成

**插件**：`op_waf` (御风OP防火墙)

**改造内容**：
- **info.json**：修改 `type` 字段为标准的枚举值 `"security"`。
- **语言包**：使用提取脚本成功抽取了所有前端 JS 与 HTML 的中文，建立并生成了 `lang/zh-CN.json` 与 `lang/en.json`。
- **前端 JS 重构**：删除了全量旧的 `owPost()` 等手动请求封装，首行注入 `var api = YfPlugin.createApi('op_waf');`。全面将请求变更为 `api.post` 和 `api.postSilent`。
- **后端安全加固**：重构了 `index.py` 中直接使用 `yf.execShell('cp -rf ...')` 等系统调用的地方，将其升级为 `yf.safeExecShell(["cp", "-rf", ...])`，及将文件创建改为原生的 `yf.writeFile()`，杜绝潜在的命令执行隐患。
- **测试结果**：Python 端入口 `status` 等验证无错误，语法静态检查通过。

**结论**：`op_waf` 的大规模流水线重构证明了我们在前期制定的方案高度可行。接下来将继续在 `mysql` 上推行相同流程。

## 2026-08-28：mysql (第二阶段) 改造完成

**插件**：`mysql` (核心数据库环境)

**改造内容**：
- **info.json**：修改 `type` 字段从不标准的中文 `"运行环境"` 修正为标准的英文 `"database"`。
- **语言包**：运行 `extract_i18n.py` 对繁杂的代码进行了中文字符串剥离，成功生成了 `lang/zh-CN.json`（约 800+ 词条）。
- **前端 JS 重构**：清除了 `myPost`, `myPostN`, `myAsyncPost`, `myPostCallbak`, `myPostCallbakN` 五个老旧的历史包袱 API，统一引入 `var api = YfPlugin.createApi('mysql');`。
- **后端脚本安全**：编写了针对 Python 后端特定的替换脚本，精确识别 `yf.returnJson()` 函数并提取其中文字符串为字典 key。
- **问题与对策**：在测试后端字典提取时，发现 `mysql` 的 `index.py` 内含有大量的字符串变量拼接构造复杂字典（如同步状态记录）。原生的 Python 字典语法由于直接的字符串替换容易被破坏，已编写 `refactor_py.py` 优化脚本使用智能过滤并自动修复了部分语法糖替换错误，保证了语法的完整性。

**结论**：`mysql` 改造完成。核心高频插件的改造极大验证了自动化辅助脚本的必要性。接下来将继续在 `openresty` 上推行相同流程。
