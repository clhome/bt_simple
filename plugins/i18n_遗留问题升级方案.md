## 一、实测核实（与待办描述的出入）

写方案前逐项实测，有三项与待办描述不符，必须先纠正，否则方案会打偏。

### 1.1 待办 2 的「38 处」实际分三类

待办描述把它们统称「拼接型消息无前缀键」。实测按**能否被 `translateAny` 的冒号前缀匹配命中**分三类：

**A 类 —— 冒号结尾前缀，补键即生效（27 条）**

| 插件 | 前缀键 |
|---|---|
| docker | `获取镜像备份列表失败:`、`导出镜像失败:`、`镜像文件不存在:`、`导入镜像失败:` |
| fail2ban | `缺少必要参数:`、`部分IP封禁失败:`、`不支持的防护类型:` |
| mariadb | `SQL执行失败:`、`源文件不存在:`、`设置数据库权限异常:`、`部分表修复未完成:`、`部分表优化失败:`、`部分表引擎转换失败:`、`设置复制用户权限异常:` |
| mysql | `数据库备份失败:`、`源文件不存在:`、`SQL执行失败:`、`设置数据库权限异常:`、`部分表修复未完成:`、`部分表优化失败:`、`部分表引擎转换失败:`、`设置复制用户权限异常:` |
| op_waf | `缺少必要参数:`、`读取日志失败:`、`删除失败:` |

> 去重后需新增的键：**23 个**（`源文件不存在:`、`SQL执行失败:`、`设置数据库权限异常:` 等在多插件重复）。
> 这 27 条**零代码改动**，只需补 23 键 × 6 语言。

**B 类 —— 无冒号碎片，前缀匹配无能为力（7 条）**

```
mariadb: '数据库用户[' ×2, '复制用户[' ×1
mysql:   '数据库用户[' ×2, '主从复制用户[' ×2
```

源形如 `'数据库用户[' + name + ']...'`。取首个 `:`/`：` 的候选键逻辑在这里取不到冒号，退化为整串比较 → 必然落空。
**必须改后端消息格式**（见 §4.2）。

**C 类 —— 含 HTML（4 条，均在 gitea）**

```python
'请先安装初始化!<br/>默认地址:http://'
```

`<br/>` 混在消息里，既违反红线 1，也让键无法作为自然语句翻译。
**必须拆分为「结构性拼接」**（HTML 由前端拼，后端只给数据）。

### 1.2 待办 1 的「无法静态校验」—— 实测能定位，且已有 1 处真 bug

实测 46 处「首参非字符串字面量」的 `pt()` 调用。绝大多数是**单参**（`pt(raw)`、`pt(orig)`），本身无害，只是静态不可验。

但其中 **1 处是多参，即真 bug**：

```js
// plugins/fail2ban/js/fail2ban.js:49
return pt(F2B_MSG_PATTERNS[i][1], m[1]);   // ← 第二参被静默丢弃
```

这与我在 `op_waf/js/op_waf.js:29` 修过的**完全同型**，当时因为「正则要求首参是字面量」而漏掉，`fail2ban` 未同步修复。
**后果**：`F2B_MSG_PATTERNS` 里 6 条模式消息（`缺少必要参数: {1}`、`IP格式错误 {1}`、`不支持的防护类型: {1}`、`部分IP封禁失败: {1}`、`未找到Fail2ban数据库: {1}`、`无法读取Fail2ban数据库: {1}`）全部显示字面 `{1}`。

> 结论：待办说「无法静态校验」不够准确 —— **用括号配对扫描（而非正则首参约束）可以 100% 定位**。见 §4.1。

### 1.3 待办 4 的归因错误

待办说「`plugins/docker/info.json` 缺少英文 `title` / `ps`」。实测：

- `plugins/docker/info.json` 是**单语言结构**，`title`/`ps` 只有中文，**这是全库 36 个插件的统一约定**（对照 `gitea/info.json` 同样只有中文）。
- 插件标题/描述的英文本来自**全局语言包** `web/static/language/en/template.json` 的 `docker.title`。
- 实测该值 = `"YufengDockerManager"`（缺空格、`YuFeng` 大小写错），而测试期望 `"YuFeng Docker Manager"`。

`test_plugins_i18n.py` 的两条失败**同一根因**，均指向全局包：

```
FAIL: test_specific_plugin_translations
AssertionError: 'YufengDockerManager' != 'YuFeng Docker Manager'
FAIL: test_yufeng_branding_in_english
AssertionError: False is not true : Plugin docker should contain 'YuFeng' in English title/ps
```

**所以待办 4 的正确处置是改全局语言包（4 处键值），不是改 `info.json`。**

## 四、逐项详案

### 4.1 【P0】动态 `pt()` 参数个数校验

#### 4.1.1 立即修复（1 行）

```diff
  // plugins/fail2ban/js/fail2ban.js:49
- return pt(F2B_MSG_PATTERNS[i][1], m[1]);
+ return msgTpl(pt(F2B_MSG_PATTERNS[i][1]), [m[1]]);
```

#### 4.1.2 静态检测器（消除「人工复核」）

**关键洞察**：不能再用「正则 + 首参必须是字面量」的思路（那正是漏掉 `fail2ban` 的原因）。
改用**括号配对 + 顶层逗号计数**，与首参形态无关：

```
扫描所有 .js / .html（含 index.html）
  ↓
轻量 tokenizer 跳过字符串 / 模板串 / 正则字面量 / 注释
  ↓
定位标识符 pt / _t 且紧跟 '('
  ↓
括号配对找到匹配的 ')'
  ↓
统计括号内「深度 = 1」的逗号个数
  ↓
逗号数 ≥ 1  →  违规（多参调用）
```

复用既有 `test/i18n_scripts/tools/check_js_quote_mismatch.js` 里已验证的 tokenizer（能正确区分除法 `/` 与正则 `/…/`、处理模板串与行延续）。

**产出**：`test/i18n_scripts/tools/check_pt_argc.js`，输出格式与既有检测器一致（`总数: N`），便于脚本化断言。

**验收**：全库 `总数: 0`；对 `fail2ban.js:49` 的**修复前版本**必须报 1 处（回归自证）。

#### 4.1.3 运行时守卫（可选，低成本兜底）

在 `web/static/app/i18n.js` 的 `createPluginTranslator` 内，给 `pt` 加参数个数告警（**不改变行为**，仅暴露问题）：

```js
function pt(key) {
    if (arguments.length > 1) {
        try {
            console.warn('[i18n] pt() 只接受 1 个参数，多余参数被丢弃；插值请用 msgTpl(pt(...), [args])', key);
        } catch (e) {}
    }
    ...
}
```

**为什么只告警不自动插值**：自动把 `pt(key, arg)` 变成 `msgTpl(pt(key), [arg])` 会**改变行为**（当前是丢弃），
若某处依赖「丢弃后取整句」，自动插值反而出错。告警是零风险的。
生产环境可通过构建期剥离 `console.warn`（或加 `window.__YF_I18N_DEBUG__` 开关）。

补齐后跑 `i18n_plugin_check.py <插件名>` 确认「硬性失败项: 0」。

#### 4.2.2 B 类（7 条）—— 统一后端消息契约

**根因**：源形如 `'数据库用户[' + name + ']...'`，无冒号，前缀匹配取不到候选键。

**方案**：确立后端消息契约 ——

> 面向用户的后端消息统一为 **`<可翻译前缀>: <动态参数>`**，分隔符必须是 ASCII `:` 或全角 `：`。

改写：

```diff
- returnJson(False, '数据库用户[' + name + ']密码重置失败')
+ returnJson(False, '数据库用户密码重置失败: ' + name)
```

**为什么这样改而不扩展前缀匹配**：若给 `translateAny` 加「首个 `[` 之前的片段」作为候选键，
`数据库用户` 这种前缀过于宽泛，极易与其他键冲突（同键冲突时先到先得，结果不可预期）。
**改后端格式比放宽匹配规则更安全、更可预测。**

同时把该契约写入 `web/static/app/i18n.js` 的 `translateAny` 注释块与 `yufeng-plugin-dev` 技能文档，防止后续回退。

#### 4.2.3 C 类（4 条）—— 拆 HTML 为结构性拼接

```python
# 现状（gitea/index.py）：消息里含 <br/>
'请先安装初始化!<br/>默认地址:http://'
```

**方案**：后端只返回**纯数据**，HTML 由前端拼（属「结构性拼接」，合规）：

```python
# 后端：拆成两个可翻译片段 + 数据
returnJson(False, '请先安装初始化!', {'url': 'http://' + host + ':' + port})
```

```js
// 前端：结构性拼接（HTML 由代码提供，文案走 pt()）
layer.msg(pt('请先安装初始化!') + '<br/>' + pt('默认地址: ') + data.url, ...);
```

> 红线复核：`'<div>' + pt(…) + '</div>'` 这类**结构性拼接**是允许的（上一轮方案已明确）。
> 被禁止的是「中文 A + 变量 + 中文 B」这种**语序依赖**的拼接。此处 HTML 是结构、文案是完整句，合规。

### 4.3 【P3，可选】后端消息结构化

#### 4.3.1 目标

彻底摆脱字符串拼接：`returnJson(False, '拉取失败: ' + e)` → 返回 `{msg_key, msg_args}`。

#### 4.3.2 关键约束：必须零破坏

直接改 `msg` 的语义会**破坏所有现有前端**（大量 `layer.msg(rdata.msg)` 直接展示）。
因此采用**旁路元数据**方案：

```python
# 新增辅助函数（web/core 或 yf 公共层）
def returnI18n(status, msg_key, msg_args=None, data=None):
    """兼容式国际化返回：msg 保持旧行为（已插值的中文），另附 _i18n 元数据"""
    payload = dict(data or {})
    payload['_i18n'] = {'key': msg_key, 'args': list(msg_args or [])}
    return returnJson(status, render_legacy(msg_key, msg_args), payload)
```

**兼容性保证**：

| 消费方 | 行为 |
|---|---|
| 旧前端（不认识 `_i18n`） | 照常读 `msg`，显示已插值的中文 —— **与改造前完全一致** |
| 新前端（`layer.msg` 拦截器） | 发现 `_i18n` 则用 `msgTpl(pt(key), args)` 渲染 → 精确翻译 |

前端接入（`public.js` 的 `layer.msg` 拦截器，已有 `translateAny` 回退点）：

```js
// 优先使用结构化元数据（若存在）
if (opts && opts._i18n && opts._i18n.key) {
    content = msgTpl(pt(opts._i18n.key), opts._i18n.args);
} else {
    content = YfI18n.translateAny(content);   // 既有回退
}
```

#### 4.3.3 渐进迁移

- **不做全量改写**（929 条），只对**新增消息**强制使用 `returnI18n`；
- 存量消息在触碰时顺手迁移；
- 收益：新消息 100% 可翻译，无需补键、无需冒号契约。

#### 4.3.4 性能影响

`_i18n` 元数据使单条响应增大约 60~120 字节。按最大 50 条批量消息估算 ≈ +6 KB，**可忽略**。
需在 P3 落地后做一次响应体埋点确认。

## 五、不破坏功能的保障措施（核心）

用户明确要求「在不破坏软件功能的前提下」。以下 6 条是硬约束：

### 5.1 兼容层优先，不做破坏性替换

| 场景 | 保障 |
|---|---|
| 后端消息结构化（P3） | `msg` 字段**语义不变**（仍是已插值中文），新信息放**旁路** `_i18n`。旧前端零感知 |
| `pt()` 多参（P0） | 只加 `console.warn`，**不自动插值**（自动插值会改变现有丢弃行为） |
| 全局包 HTML（P2） | 保留 `reboot_panel_wait_msg` 的 HTML（有测试断言 + 功能依赖），走白名单 |
| 后端消息契约（P2） | 只改**新写**的消息；存量在触碰时迁移，不批量重写 |

### 5.2 每个阶段单一关注点，可独立回滚

- 一个阶段 = 一个（或少数几个）commit；
- **CRLF 换行统一必须单独 commit**，与内容变更完全隔离（否则 revert 会连带丢内容）；
- 每阶段结束跑全量验收，绿了才进下一阶段。

### 5.3 冻结回归基线

开工前先记录当前基线（已知全绿项 + 已知基线失败项），改完后逐项比对：

新增检测器必须**先对已知问题版本报错**，再确认修复后归零。例：
`check_pt_argc.js` 跑在 `fail2ban.js` 的**修复前**副本上必须报 1 处。

否则无法排除「检测器写错、恒返回 0」的假绿。

### 5.5 语言包写入的三条纪律（沿用上一轮）

1. 保持各插件**原有缩进**（fail2ban `indent=4`，op_waf `indent=1`）；
