### 关键发现 1：`msgTpl()` 不会翻译

`web/static/app/public.js:540`：

```js
function msgTpl(msg, args) {          // 纯字符串替换，不含 pt()
  if (typeof args == 'string') { return msg.replace('{1}', args); }
  ...
}
```

因此 `msgTpl('您真的要{1}{2}{3}服务吗？', [d,a,v])` 渲染出的是**中文原文**。全库 14 处 `msgTpl` 调用中 **13 处漏包 `pt()`**：

| 插件 | 漏包数 |
|---|---|
| apache | 4 |
| openresty | 4 |
| supervisor | 1 |
| yufeng_systemd | ✅ 正确写法参考（`msgTpl(pt(...))`） |

正确写法：
```js
layer.confirm(msgTpl(pt('您真的要{1}{2}{3}服务吗？'), [d, a, v]), ...)
```

### 关键发现 2：语言包里混入了「功能代码」

这是本次用户明确要求解决的问题。共 **133 个脏键**，其中 104 个是**提取脚本产生的纯垃圾**：

```jsonc
// task_manager/lang/zh-CN.json（82 个同类）

// openresty/lang/zh-CN.json（22 个同类）
"关闭', '关闭"

```

```jsonc

// clean（HTML 混入翻译值，硬红线）

```

这些键**永远不会被命中**（运行时查不到），只会让语言包膨胀、难以审阅。

## 二、升级方案（5 个阶段）

### 阶段 1 —— 语言包标准化（用户核心诉求，P0）

**目标：语言包里只留「人能读的自然语句」，不留任何功能代码痕迹。**

| 子项 | 数量 | 处理方式 |
|---|---|---|
| 1.1 提取垃圾键（`X', 'X` 模式） | 104 | 直接删除（干净键已存在，冗余） |
| 1.2 译文含 HTML | 12 | 标签移回代码，纯文本入包 |
| 1.3 转义序列键（`\n` 等） | 10 | 拆成 `'\n' + pt('...')` 形式 |
| 1.4 JS 拼接键 | 12 | 改 `{1}` 位置占位符模板 |
| 1.5 纯标点键 | 1 | 删除 |

6 个语言包同步增删，保证键集完全一致。

### 阶段 2 —— 修复 `msgTpl` 未包 `pt()`（P0，9 处）

apache / openresty / supervisor 共 13 处调用改为 `msgTpl(pt('...'), [...])`。

### 阶段 3 —— 补齐 JS 缺键 + 拼接串模板化（P1）

- **89 处** JS 中文字面量缺语言包键 → 补 6 语言键 + 包 `pt()`
- **146 处** 拼接串按红线 2 改为整句模板：

```js
// 改造前 ❌ —— 永远查不到译文，且语序无法本地化
safeMessage(pt('删除') + ' [' + name + ']', '您真的要删除【' + name + '】吗？', fn)

// 改造后 ✅
safeMessage(msgTpl(pt('删除 {1}'), [name]), msgTpl(pt('您真的要删除【{1}】吗？'), [name]), fn)
```

### 阶段 4 —— zh-TW 繁体化（P2）

复用 `test/i18n_scripts/zh_tw_convert.py`（opencc `s2twp`），仅转换「值与简体原文完全相同」的条目，已有译文不动。

### 阶段 5 —— 验证与回归守卫（P0）

新增 `test/test_plugins_i18n_upgrade.py`（标准库 `unittest`），锁死：

1. 六语言键集与 zh-CN 完全一致（无缺失 / 无多余）
2. 译文不含 HTML（红线 1）
3. 语言包无脏键（正则黑名单）
4. 所有 `msgTpl(` 调用内必须含 `pt(`
5. `index.html` 中文串 100% 有键
6. `pt()` 字面量 100% 有键

## 三、必须遵守的红线（沿用 + 强化）

| # | 红线 | 校验点 |

## 六、第二轮：深挖后的补充修复（2026-09-21 续）

首轮验收全绿后，用更严格的判定重新扫描，又发现并修复了 4 类问题——
它们都不会被「键是否存在」这类检查发现。

### 6.1 死键判定升级：从「子串命中」到「整串引用」

首轮的死键检测用 `if 键 in 源码` 判定，会把 `上行速度：` 误判为「仍被引用」，
因为它是 `上行速度：{1}/秒` 的子串。改为**整串边界匹配**后，暴露 196 个真死键：

| 类别 | 数量 | 处置 |
|---|---|---|
| 被同包更长键取代的碎片（如 `删除[`、`] 吗？`、`确定要`） | 129 | **删除** |
| 后端 `returnJson` 消息的静态前缀（如 `拉取失败:`、`清空失败:`） | 67 | **保留**（见 6.4） |

> 判定规则：键必须是**完整的字符串字面量**（`'键'` / `"键"`），
> 或独占一个 HTML 文本节点（`>键<`，含「片段以键结尾」的 `>键'`）。
> 另设例外：若键是插件 `.py` 中某个中文字面量的子串，视为「后端预留」保留。

### 6.2 `{0}` 起始占位符 —— `msgTpl` 永远填不上

`msgTpl()` 从 `{1}` 开始替换（`public.js:540`），因此 `{0}` 占位符永远保持字面量。
共 9 处，全部在 `index.html`（首轮的扫描只覆盖 `js/` 目录，漏掉了）：

| 文件 | 键 | 处置 |
|---|---|---|
| `pg_docker/index.html` | `确定要切换为【{0}】吗？` | 键改 `{1}`，源码改 `msgTpl` |
| `pg_docker/index.html` | `确定要{0}实例 [{1}] 吗？` | 键改 `{1}`/`{2}` |
| `pg_docker/index.html` | `确定要{0}实例 [{1}] 的自动备份计划任务吗？` | 同上 |
| `pg_docker/index.html` | `正在{0}...` | 键改 `{1}` |
| `pg_docker/index.html` | `正在{0}自动备份...` | 键改 `{1}` |

### 6.4 后端消息回退翻译（本轮最大收益）

**问题**：插件后端 `index.py` 通过 `returnJson(False, '拉取失败: ' + e)` 返回的中文消息，
前端以 `layer.msg(rdata.msg)` / `showMsg(rdata.msg)` 直接展示。而这些消息的原文
**正是插件语言包的键**——但全局翻译器 `t()` 只查 `window.lan` 的点号路径，
从不查插件字典，所以此前**恒显示中文**。

**量化**（36 个插件）：

| 类型 | 数量 | 说明 |
|---|---|---|
| 纯字面量消息，且键已存在 | **695** | `translateAny` 精确匹配即可翻译 |
| 拼接型消息（`键 + 变量`），且冒号前缀键已存在 | **117** | 走冒号前缀匹配 |
| 拼接型消息，键缺失 | 38 | 需补键（未处理，见待办） |
| 合计可翻译 | **812 / 929（87%）** | |

**实现**：

1. `web/static/app/i18n.js` 新增 `translateAny(text)` 并挂到 `window.YfI18n`：
   - ① 全局字典 `t(key)`；② 所有已加载插件字典（`window._pluginDicts` 服务端直出 + 异步缓存）**精确匹配**；
     ③ **冒号前缀匹配**——取消息首个 `:` / `：`（含）作为候选键再查一次，
     命中则替换前缀、保留变量部分（对应 `键 + 变量` 型后端消息）。
   - 性能：合并索引懒构建 + 单条结果缓存 + 字典数量变化自动失效重建；全程 `try/catch` 包裹。
2. `web/static/app/public.js` 的 `layer.msg` 拦截器（原注释即「增强 layer.msg 国际化」）
   在全局字典未命中时接入 `translateAny` 回退。`showMsg()` 内部走 `layer.msg`，一并覆盖。

**行为测试**：`test/i18n_scripts/tools/test_translate_any.js`（Node 最小 window/document 替身，
11 条断言，含前缀匹配、同键冲突、无键原样、字典热加载）。

## 七、第三轮：`参数:(` 碎片键与动态 `pt()` 失效

### 7.1 `checkArgs()` 碎片拼接（27 个插件）

每个插件的 `index.py` 都有同一段参数校验：

```python
def checkArgs(data, ck=[]):
    for i in range(len(ck)):
        if not ck[i] in data:
            return (False, yf.returnJson(False, '参数:(' + ck[i] + ')没有!'))
```

这句在语言包里制造了两个**脏键**：`参数:(` 与 `)没有!`——
正是用户要求清除的「功能代码式内容」，且两半都无法独立翻译
（`参数:(` 在英语里是 `Parameter:(`，`没有!` 是 `is missing!`，拼接后语序全错）。

改为单一完整消息：

```python
            return (False, yf.returnJson(False, '缺少必要参数: ' + ck[i]))
```

前端 `layer.msg` 拿到 `缺少必要参数: xxx`，由 `translateAny()` 的**冒号前缀匹配**
命中新键 `缺少必要参数:`，从而正确本地化。

| 动作 | 数量 |
|---|---|
| 改写源码（`plugins/*/index.py`） | 27 个插件 / 27 行 |
| 新增键 `缺少必要参数:` | 27 × 6 语言 |
| 删除脏键 `参数:(` / `)没有!` | 27 × 2 键 × 6 语言 |

> `op_waf` 此前已修（`index.py:68` 有说明注释），故本次不在改写范围内。
> 脚本：`test/tmp_i18n/fix_checkargs_fragments.py`（按行改写，跳过注释行，
> 避免把 `op_waf` 里作为对照保留的旧写法一起改掉）。

### 7.2 `wafMsg()` 动态 `pt()` 多参失效

`plugins/op_waf/js/op_waf.js`：

```js
return pt(WAF_MSG_PATTERNS[i][1], m[1]);   // 键是 '缺少必要参数: {1}'，m[1] 被静默丢弃
```

由于第一个实参不是字符串字面量（是数组下标），此前所有「多参 `pt()`」扫描
（正则要求首参是字面量）都扫不到它。用户实际会看到字面 `{1}`。

已改为 `return msgTpl(pt(WAF_MSG_PATTERNS[i][1]), [m[1]]);`

> **教训**：动态键 `pt(someVar)` 的参数个数无法用正则静态校验，
> 只能靠 `msgTpl` 调用点的显式审查。回归测试已覆盖字面量场景，
> 动态场景依赖人工复核（`i18n_plugin_check.py` 的「待复核」项）。

### 7.3 `task_manager` 非中文技术标签补键

`pt('CPU')` / `pt('PID')` / `pt('PTS')` / `pt('CPU：')` 四个字面量被 `pt()` 包裹，
但语言包无键 —— 项目自带检查器 `i18n_plugin_check.py` 记为硬性失败项。
已补齐（`CPU：` 在拉丁语系改为半角 `CPU:` / `CPU :`）。
